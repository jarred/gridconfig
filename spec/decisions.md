# Decisions and open questions

The decisions that shaped the [spec](./spec.md), and the questions that are still open. Each item says if it is decided, deferred, or open.

- **Hiding (decided for v1, to revisit).** Hiding stays `display: none !important`, not in a layer. Watch for page authors who need an absent area to stay visible. If this is necessary, the candidate is a `keep: [B]` setting. The setting skips the hide rule. It also sets `grid-area: auto` for that area in the step. A possible later alternative is a style-query output profile. It uses a custom property for each area, and it does not use exclusive `not (…)` ranges. It raises the minimum browser version.
- **Custom properties (decided for v1).** The gap and the padding are in `--grid-gap` and `--grid-padding`, the same prefix as `--grid-step`. The first names were `--gap` and `--padding`. They hid the `--gap` of a page from all content in a grid, and `gap: --gap` referred to itself.
- **Calculated rows (decided for v1).** With `container: inline-size`, the rows that the compiler calculates are `auto`, not `1fr`. With `1fr`, a stack such as `image`, `title`, `text` gave each row the height of the image. If the page gives the host a definite height, the `auto` rows still fill it, because a grid stretches its `auto` tracks. To get equal rows there, set `rows`. The columns stay `1fr`. A change to `minmax(0, 1fr)`, so that content cannot make a column wider, is open.
- **Options of a project (decided for v1).** The build plugin gives its options to the page, and `createGrid` makes a `grid` with options. Before this, only the plugin had the options. A layout that compiled when the code ran did not know the breakpoints of the project, and it used the default layer. `tokenVar` stays out of the options that the plugin gives, and out of the name hash, because it is a function.
- **Runtime stylesheets (decided for v1).** Core has `mountStyles`, and the adapters use it in the browser. Before this, the Svelte adapter wrote the CSS one time for each grid, and the React adapter kept the old CSS of a layout that changed, so a step that the new layout did not have still applied. Open: the HTML that the Svelte adapter makes on the server still has the CSS one time for each grid. To write it one time, the adapter needs a component around the page that collects the layouts.
- **Anchors and aliases (decided for v1).** A `.grid` file cannot have YAML anchors or aliases. A tool that writes a layout file cannot keep them, and one value in two places is hard to read in a small file. To permit them later does not break a layout.
- **Layer (decided for v1).** Layers are on by default, in the layer `gridconfig`. The reason: a utility class such as `gap-4` must be able to override a layout. The cost: an unlayered reset such as `* { padding: 0 }` removes the layout padding, in any source order. A page can put its reset in an earlier layer to prevent this. Browser tests record both cases. The hide rules stay outside the layer, because `!important` reverses the order of layers.
- **Names (decided for v1).** The function is `grid`. It matches the `.grid` extension, the package name, and the `data-grid-*` attributes. The result of `grid` is a layout, and a component takes it as a `layout` prop. The query for a plain YAML file is `?grid`. It is not `?layout`, because SvelteKit uses "layout" for route layouts. An import of `grid` can use an alias, for example `import { grid as g }`, if a file already has a variable `grid`. The build plugin follows the alias. The plugin does not compile the calls in a file that gives the name `grid` to a different variable. Those calls compile when the code runs.
- **Flow (later).** Reverse directions (`row-reverse`, `column-reverse`) and shared entries (`B C: column`) are not in v1. The inspector can show the flow of an area next to its label. A future per-area setting (`keep`, or a per-area `css`) must use the same shape as `flow`: a map from the area name to a value.
- **Named steps (partly decided).** [Named breakpoints](./format.md#named-breakpoints) give a short value to `--grid-step`. A style query for a key with dots, slashes, or spaces works in Chromium. Do a test in other browsers before we recommend it.
- **Units in keys (later).** Keys in `rem` follow the font size of the user. To keep the [one-winner rule](./format.md#cascade-semantics) exact, a layout must use one unit in all its keys.
- **Tools for the step order (later).** The data of the regions can give a `gridconfig explain` command (the step that sets each property at a size) and a map of the steps in the inspector.
- **Reactive step (deferred).** The adapters can give the active step to JavaScript, for logic such as a change of component. The value comes from `--grid-step`, with a `ResizeObserver` on the host. Styles do not need it: use the style query.
- **Identifiers.** The container names and the selectors are the `name` of the layout. A name that the compiler makes (a file name or a hash) has a low risk of conflict inside one project. Do production builds add a short hash to prevent a conflict between packages?
- **Token breakpoints (decided).** Named breakpoints replace `{bp.md}`. The `breakpoints` option gives names to all layouts at build time, because `var()` cannot be in a container condition.
- **`css` escape hatch.** Raw declarations do not work in the same way in the shadow-DOM output. Decide if the shadow-DOM output permits them.
